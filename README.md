# Broker Hub 项目需求简报（访谈优先版）

> 版本：V1.0  
> 整理日期：2026-09-06  


## 1. 一句话定位

面向海外华人的社区型信息交流平台，先聚集瑞士当地华人，通过分区、发帖、评论、私聊、活动和个人信息展示，形成一个可信的本地生活社区；后续再逐步延伸到国内用户、代购、物流和交易服务。

## 2. 项目重点

### 2.1 核心不是商城，而是社区

- 产品气质应接近“海外华人家园 / 社区 / 论坛”，而不是美团式平台。
- 重点是把分散在微信群、宝妈群、留学生群中的用户聚集到一个可持续运营的平台。
- 用户可以围绕生活、育儿、交友、求职、二手物品、互助和个人服务进行交流。
- 平台早期主要提供信息展示和沟通，不介入用户之间的线下资金往来。

### 2.2 一期先验证瑞士本地社区

- 第一阶段重点是瑞士端，优先服务当地华人、宝妈、留学生和有个人服务/物品发布需求的用户。
- 先验证用户是否愿意注册、发帖、评论、私聊、发布物品或活动。
- 不要在一期同时建设国内买家端、正式跨境代购和复杂交易系统。

### 2.3 内容要分区，不能全部混在一起

访谈中明确希望通过板块区分内容，初始板块可包括：

- 宝妈/育儿及亲子交流。
- 免费赠送或交换。
- 二手物品交易信息。
- 求助和互助。
- 招聘、求职及兼职信息。
- 回国行李/物品信息。
- 活动发布与组团。
- 生活交流及其他运营板块。

板块不是写死的，后台应能按运营需要新增、调整、隐藏或删除板块。

### 2.4 个人用户是主要供给方

- 平台主要面向个人用户，而不是传统商家入驻平台。
- 用户可以发布自己的物品、服务、活动或需求。
- 可以有“口袋店铺/个人主页”概念，用于集中展示个人发布的内容。
- 一期的物品信息只做展示和联系，成交由用户自行线下完成。

### 2.5 信任和风控是基础能力

访谈反复提到骗子、纠纷、食品资质、夹带/人肉、代购风险等问题，因此一期必须具备：

- 内容审核和敏感词过滤。
- 违规内容删除。
- 用户禁言、封禁和解除封禁。
- 举报/投诉或至少可联系平台客服的入口。
- 清晰的社区规则、风险提示和平台责任边界。
- 对高风险内容进行人工审核，不能只依赖用户自行发布。

## 3. 一期目标

> 上线一个可在瑞士真实运营的社区 MVP：用户能够注册、完善资料、进入不同板块、发帖交流、私聊、发布活动和展示个人物品/信息；运营人员能够管理板块、审核内容、处理违规用户和提供客服支持。

一期不追求完成交易闭环，重点是先形成“用户进入 → 发布内容 → 产生交流 → 建立信任 → 产生真实需求”的社区闭环。

## 4. 一期功能清单

### 4.1 账号与个人资料（P0）

- 用户注册、登录和退出。
- 个人资料：头像、昵称、简介等基础信息。
- 个人主页：查看用户发布的帖子、物品和活动。
- 用户之间可以从个人主页进入私聊。
- 为后续用户身份、代购认证和信用信息预留扩展空间，但一期不强制做完整实名认证。

### 4.2 首页与社区入口（P0）

- 首页展示社区内容和运营推荐内容。
- 展示不同板块入口。
- 展示个人发布的物品/服务信息。
- 展示活动和重要公告。
- 首页可预留广告或推荐位。
- 支持运营人员手动调整首页展示内容。

### 4.3 板块管理（P0）

用户侧：

- 查看板块列表。
- 进入板块查看帖子。
- 在指定板块发布对应内容。
- 内容必须归属某个板块，避免所有信息混杂。

后台侧：

- 新增板块。
- 编辑板块名称、简介和排序。
- 隐藏或删除板块。
- 设置板块展示状态。
- 管理板块下的帖子。

一期建议先配置：免费赠送/交换、二手交易、求助互助、招聘求职、回国行李、宝妈交流、活动等板块。

### 4.4 发帖与内容交流（P0）

- 发布帖子。
- 编辑和删除自己的帖子。
- 帖子包含标题、文字内容和图片。
- 帖子选择板块和相关标签。
- 查看帖子详情。
- 在帖子下评论和回复评论。
- 对帖子进行基础互动。
- 帖子支持后台审核、隐藏、删除和恢复。
- 帖子可关联个人物品、活动或求助信息。

### 4.5 私聊（P0）

- 用户与用户一对一文字私聊。
- 从帖子、个人主页或物品信息进入私聊。
- 查看会话列表。
- 显示基础未读状态。
- 用户可以拉黑对方或向平台反馈聊天问题。
- 一期不做语音、视频、直播和复杂公开聊天室。

### 4.6 活动发布（P0）

用于宝妈约玩、亲子活动、聚会、出游和其他线下活动。

- 发布活动。
- 填写活动标题、说明、时间、地点/区域和人数等信息。
- 查看活动详情。
- 用户表达参加意愿或报名。
- 发起人查看参与人员。
- 活动发布到相应社区板块。
- 活动支持后台审核、下架和关闭。
- 活动页面显示线下活动风险提示。

一期只做活动信息和报名/联系，不代收活动费用。

### 4.7 个人物品/“口袋店铺”展示（P0）

- 用户创建个人物品信息。
- 填写物品名称、描述、图片、所在地区和联系方式设置。
- 物品状态可设置为“在售/可交换/免费赠送/已完成”。
- 用户可以把物品发布到对应社区帖子中。
- 其他用户查看物品详情后发起私聊。
- 个人主页集中展示该用户的物品信息。
- 用户自行在线下沟通和交易，平台一期不收款、不担保、不分账。

重点覆盖访谈中提到的：生活用品、回国前处理物品、免费赠送、交换和低价二手物品。

### 4.8 回国行李信息（P1，建议一期纳入）

- 用户填写预计回国时间、出发地/目的地和可提供的信息。
- 信息可长期展示在“回国行李”板块。
- 其他用户查看后通过私聊联系。
- 平台只做信息展示和风险提示，不承诺运输、不代收费用、不处理清关。

该功能涉及当地法律、报税、违禁品和夹带风险，具体发布规则必须在上线前确认。

### 4.9 求助、招聘及个人服务信息（P1，建议一期纳入）

- 发布求助、兼职、招聘或个人服务信息。
- 通过板块和帖子进行展示。
- 其他用户通过评论或私聊联系发布者。
- 平台可以删除违法、诈骗、明显高风险或不合规内容。
- 一期不做平台撮合佣金、合同、在线支付、接单结算或服务结果担保。

### 4.10 后台管理与客服（P0）

用户管理：

- 查看用户基础资料。
- 禁言、封禁和解除封禁。
- 处理用户投诉、纠纷和违规记录。
- 管理用户发布的帖子、物品和活动。

内容管理：

- 审核、隐藏、删除和恢复内容。
- 配置敏感词或违规关键词。
- 处理疑似诈骗、违禁品、违法广告和高风险服务信息。
- 对回国行李、食品、招聘、线下服务等内容设置专门规则。

运营管理：

- 管理板块。
- 管理首页推荐内容和广告位。
- 管理活动、公告和用户反馈。
- 查看基础内容和用户数据。

客服：

- 提供线上客服/问题反馈入口。
- 接收用户投诉和纠纷信息。
- 对处理结果进行记录。

## 5. 一期明确不做

以下内容虽然在访谈中被提到，但明确属于后续阶段，不纳入一期开发范围：

- 国内买家端或独立中国端。
- 正式代购订单系统。
- 竞价/拍卖列表、代拍和出价管理。
- 平台担保支付、冻结资金、定金和押金。
- 自建钱包、分账、提现和退款。
- 平台抽成和交易佣金。
- 跨境物流下单、物流费用结算和清关。
- 完整的物流轨迹查询服务。
- 代购人员的证件上传、人脸识别和正式认证体系。
- 代购信用等级和完整交易记录体系。
- 自动匹配代购、自动派单和拼邮交易闭环。
- 食品交易的资质核验和平台担保。
- 复杂的国内外双端业务流程。

一期可以为上述功能预留数据字段和接口边界，但不能为了未来功能扩大当前交付范围。

## 6. 后续阶段方向

### 阶段二：国内需求与代购连接

- 国内用户发布代购需求。
- 海外代购人员查看需求并主动接单。
- 买家与代购直接沟通。
- 代购身份、海外居留证明和人脸信息认证。
- 拍卖/代拍需求列表和时间提醒。
- 拼邮需求发布和承接。
- 物流选择与物流跟踪。
- 交易记录和基础订单状态。

### 阶段三：平台交易和商业化

- 双方约定后的平台托管/冻结资金。
- 支付、退款、争议处理和责任边界。
- 物流服务收入。
- 代购交易抽成。
- 多国家和多地区扩展。

以上阶段必须在一期社区活跃、用户信任和合规边界明确后再启动。

## 7. 一期用户闭环

```text
注册账号
  → 完善个人资料
  → 进入瑞士华人社区
  → 选择板块
  → 浏览或发布帖子
  → 评论交流
  → 查看个人物品/活动/求助
  → 私聊联系
  → 线下自行沟通
  → 举报问题或联系客服
```

## 8. 一期验收重点

### 用户端

- 用户能注册并完善个人资料。
- 用户能浏览和切换板块。
- 用户能在指定板块发布文字和图片内容。
- 用户能评论、回复和私聊。
- 用户能发布活动并让其他用户表达参加意愿。
- 用户能创建物品信息并标记完成状态。
- 用户能从帖子、物品或个人主页进入私聊。
- 用户能举报问题或联系平台客服。

### 运营端

- 运营人员能新增、编辑、隐藏和删除板块。
- 运营人员能审核、隐藏和删除帖子、物品及活动。
- 运营人员能禁言和封禁用户。
- 运营人员能处理违规内容和用户反馈。
- 运营人员能配置敏感词和基础首页推荐。
- 所有重要管理操作能够留下记录。

### 边界验收

- 一期不出现平台收款、托管、分账或提现流程。
- 一期不把代购、拍卖和国内端误做成正式交易功能。
- 合法内容可以正常发布，违法、诈骗、违禁或明显高风险内容能够被拦截或下架。
- 用户能够明确看到线下交易和线下活动的风险提示。

## 9. 当前待确认事项

以下内容在访谈中有方向，但还没有形成足够明确的产品规则，开发前必须确认：

1. 一期首发范围是否仅为瑞士，具体城市有哪些。
2. 一期交付形态是先网页版验证，还是同步提供 iOS/Android 套壳版本。
3. 初始板块的最终名称、排序和每个板块允许发布的内容类型。
4. 是否允许用户直接发布食品、代购、人肉带物和照护类信息。
5. 回国行李板块的法律边界、免责声明和禁止内容清单。
6. 招聘、兼职、看房、看孩子等服务是否只做信息展示。
7. 私聊是否允许发送图片、联系方式和外部平台账号。
8. 线上客服由谁负责、响应时间和纠纷处理标准。
9. 是否需要中文以外的语言版本。
10. 服务器部署区域、数据存储和隐私合规方案。

## 10. 需求更新规则

- 本文件以访谈原文为最高依据。
- 新增需求必须标注来源、阶段和优先级。
- 与访谈冲突的旧规划不自动继承，以访谈最新确认结果为准。
- 未经确认的功能只能放入“待确认”或“后续阶段”，不能直接进入一期开发清单。
- 每次需求变更应同步更新“一期功能清单”“明确不做”和“当前待确认事项”。
